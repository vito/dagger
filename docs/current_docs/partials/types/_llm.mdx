The `LLM` type initializes a Large Language Model (LLM).

An `LLM` acts through tools. `withWorkspace` exposes a workspace's modules as tools, the way the Dagger CLI serves them. `withTools` exposes the methods of one object.

Two builtin tools for writing [Dang](https://github.com/vito/dang) are always available, whatever the `LLM` is bound to:

- `DangCheck` type-checks Dang and describes values, types and members, without running anything.
- `DangEval` runs a Dang snippet and returns its output and result. It can make any API call: the core API, the workspace's installed modules, or a module's API (with `at`). This includes containers with network access, and reading the bound workspace through `ws`. Its calls have no access to the host.

Both see the bound workspace as `ws` and each object bound with `withTools` by its type name (`editor` for an `Editor`). `DangEval` writes by assignment only: when a snippet succeeds, a reassigned `ws` (`ws = ws.withChanges(editor.edit(source: ws, ...))`) is applied to the workspace, and a reassigned tool object (`editor = editor.todoWrite(...)`) becomes that tool's state. A snippet that fails writes nothing, and a workspace or changeset it only returns is not applied.
